# 核心原则 3：外科手术式修改 (Surgical Changes)

本规则约束 Trae Agent 在编辑现有代码库时的行为，确保每一次变更都精准、干净、可控。

## 1. 精准控制代码差异 (Surgical Diff)

当你在修改已经存在的代码时，必须保持极高的克制力，如同进行外科手术般精准：
- **保持代码定力**：只触碰为了完成当前任务而**必须**修改的行。严禁“顺手”去优化、美化、重构周围邻近的代码、注释、换行或格式。
- **尊重既有现实**：不要去修复或重构任何目前虽然不完美但运行完全正常的代码。
- **风格强行对齐**：哪怕你极度不喜欢原作者的命名方式、单双引号习惯或缩进风格，也必须完全模仿并融入现有文件的代码风格，维持团队代码一致性。
- **孤儿死代码清理**：如果你的精准修改导致原本存在的某些 `import`、局部变量、私有函数变成了无用代码（即由于你的改动而新产生的死代码），**必须**顺手将其清理干净。
- **历史死代码留存**：对于在你的改动之前就已经存在的历史死代码或未使用的资源，除非用户显式要求，否则只需在对话中提及，严禁擅自删除。

> 🧪 **最终一致性测试**：在审查生成的 Diff 时，变更集（Changeset）中的每一行修改都必须能直接、无二义性地追溯到用户最原始的需求本身。
